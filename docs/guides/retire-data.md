# 清理或移动已登记数据的固定流程

**结论：已登记的数据不能先删再补。** 任何删除、移动、重命名、替换格式的操作，都必须先找出依赖方，处理完依赖，再动文件，最后全库检查。否则会出现“索引还在、文件没了”的空地址，训练读到时才报错。

适用范围：`catalog/` 里任何产物引用的目录或文件，包括音频、清单、索引、特征。

## 步骤

| 步骤 | 做什么 | 命令 / 位置 |
|---|---|---|
| 1. 找依赖 | 列出哪些版本引用了要动的路径。只给 catalog 路径只查产物路径；加 `--roots` 会逐行扫描所有 `audio-index`，能发现只在索引里出现的引用（慢，但删之前必须跑） | `audio-data-contract find-dependents catalog <root_alias>:<相对路径> --roots roots.json` |
| 2. 确认替代 | 每个依赖版本要有一个可读的替代：同内容的其他格式、新版本，或确认不再需要。删除的依据是“替代里有同一份内容”，用文件名对应加抽样比对时长，不能只凭名字 | 替代版本需先登记并通过 `check-registration` |
| 3. 标记停用 | 不能继续读的旧版本，在 catalog 的 `provenance` 下写 `retired`，指向替代版本。版本身份、哈希和历史记录保留，不改写 | 见下方格式 |
| 4. 再动文件 | 前三步完成并合入后，才删除或移动 | — |
| 5. 全库检查 | 在有数据的机器上检查所有未停用版本是否指向空地址，必须全部通过 | `audio-data-contract check-dangling catalog --roots roots.json` |
| 6. 记录 | 在 PR 或对应的 `docs/history/` 里写明：动了什么、释放多少空间、替代是什么 | — |

不要用软链把旧版本目录指到新版本：旧版本的产物登记了 `sha256` 和记录数，软链后内容不同，校验会失败，也会悄悄丢记录。

## retired 格式

```yaml
provenance:
  retired:
    date: '2026-11-04'
    superseded_by: emilia2_short@short-lance-20261023   # 可选；必须是已登记的版本
    reason: 音频 m4a 已按 Lance 发布里的同一份 FLAC 清除
```

- 载入 catalog 时会检查 `superseded_by` 指向的版本确实存在。
- `check-dangling` 跳过已停用版本，因此停用版本允许指向已删除的文件；正在使用的版本不允许。
- 停用不等于删除声明：版本说明、血缘和 View 引用仍保留。仍有未停用版本引用它时，`find-dependents` 返回非零状态。

## 检查的边界

- `check-dangling` 对每个版本的每个产物检查文件存在，对 `audio-index` 按固定种子抽样 `--sample` 条（默认 20）确认文件可读，不重算哈希。抽样不能保证每一行都存在；要确认某个目录下是否还有引用，用 `find-dependents --roots`。
- 它需要能访问数据的机器，CI 里没有数据，所以不在 CI 中运行。每次清理数据后、以及合并涉及索引的 PR 前，在数据机器上手动跑一次。
